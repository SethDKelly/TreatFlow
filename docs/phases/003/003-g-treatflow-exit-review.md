### Findings by specification dimension

**Purpose and OP:** each candidate has a meaningful or at least falsifiable characteristic human-facing story. A conditional candidate's story is sufficient for Phase 004 to ask whether it is independent; it is *not* a finding that the independent concept must survive.

**Abstract state and actions:** conceptual memory and user/system-significant actions are explicit. No candidate depends directly on another application's private state or a chosen persistence representation. Some actions require legitimately supplied abstract authority or eligible evidence; these are visibly **unresolved policy/composition seams**, not silently implemented permission machinery.

**Invariants and time/history:** 003-F reconciled material omissions before exit: observed silence requires reporting completeness, competing source claims stay contested, revision successors are not arbitrarily current, accepted stewardship requests do not mutate external concepts, and suspensions do not erase prior releases. OP stories can be interpreted using the written conceptual semantics.

**Under-specification:** data structures, algorithms, technical clocks, authentication technology, query/export formats, display and storage remain deliberately unspecified. Which concept should own correction, provision or contributor control is an **open factoring question**, not an acceptable unspecified behavior. Later legal consent, safe-release criteria, actor authority and empirical validity are **unresolved external design/validation obligations**, not proofs afforded by this exit.

## 4. Independence, representation and knowledge integrity

**Independence:** the five canonical owners use abstract identities rather than importing a peer concept's internal types. Their explicit dependencies concern future *composition*, not intrinsically encoded synchronizations. Risks remain at four seams: Observation/Exposure; Observation/Revision; contributor stewardship/authority and provenance; Controlled Disclosure/Research Provision. These are Phase 004 subject matter, not Phase 003 exit blockers because the semantics to assess them are sufficiently explicit.

**Representation:** no concept has been specified as an API, relational schema, object class, event stream, queue, UI screen, cloud service, runtime scheduler or implementation module. Apparent action names describe semantic transitions. Phase 005 synchronization, Phase 006 dependencies and Phase 007 experience mapping have not been preempted.

**Knowledge authority:** [purpose baseline](../../canonical/purpose/purposes.md) and [project intake](../../canonical/project/intake.md) remain unique sources for purposes and context. [Candidate directory/owner](../../canonical/concepts/candidates.md) is a provisional directory, not a second behavioral definition; the five natural canonical owners contain current specifications. Phase history documents decisions. Updated navigation and candidate status do not assert that the concept count or boundaries are final. Affected Markdown references and expected files were inspected; this is a scoped documentation audit, not a claim of exhaustive validation of the inherited template corpus.

**Decision:** no found purpose/OP/state/action/invariant omission or knowledge-graph defect requires reopening Phase 003 before *beginning* Phase 004. The conditional concept identities are intentionally not called validated.

## 5. Phase 004 challenge inventory and required handoff

The [Phase 004 definition](../004/phase-definition.md) governs specificity, minimal completeness, independent semantics, genericity and actual boundary changes. [004-A](../004/004-a-start-gate.md) should derive the project-specific subphase plan after challenging:

1. **Observation ↔ Exposure:** does watched-time coverage have a separate independent purpose, or is it intrinsic to a coherent observation account? Keep explicit zero/completeness semantics either way.
2. **Observation ↔ Revision:** is historical factual supersession intrinsically part of observation, or can Revision fulfill a generic independent end-to-end purpose beyond an edit fragment? Specify ownership after any merge.
3. **Contribution Stewardship ↔ contribution provenance:** does control-request/standing form a genuine user-facing concept, or should it become authority within another concept? Avoid coupling household, source and public researcher identity.
4. **Controlled Disclosure ↔ Research Provision:** distinct decision about future availability versus inquiry-specific evidence fitness, or a single behavior with a qualified output? A file/container is not automatically a concept.
5. **Completeness and specificity:** can any concept accomplish its own OP without hidden cross-concept behavior; do any combine unrelated purposes or preserve unjustified data?
6. **Genericity:** where only identity matters, can abstract parameters reduce accidental application coupling without obscuring temporal observation, consent or research meaning?
7. **Future Phase 005 seams:** correct assertions, permitted releases and qualified research results will need coordination only *after* stable independent boundaries exist; do not encode orchestration within a concept.
8. **Alternative validity:** retain Phase 002 contrasting decompositions as genuine counter-hypotheses, not merely historical names.

Phase 004 must update and possibly consolidate canonical specifications when a candidate is merged, split or rejected. **The five original candidates are not a required final catalog.**

## 6. Remaining external obligations and reopening conditions

- **Before real participation/collection/release:** qualify age eligibility, guardian/household consent concerns, visitor/child privacy, actual data minimization, reidentification threat, retention/withdrawal and applicable law. No "safe because abstract" inference.
- **Before research claims:** verify which event units/exposure data can support which analyses; assess voluntary selection, missingness, rate changes, clustering, sensitivity and reproducibility. The Poisson premise must remain falsifiable.
- **Before deployment:** operator capacity, actionable incident/dispute response, effective authority protections and sustainable maintenance.

If Phase 004 demonstrates that none of the surviving candidate boundaries can meet P-01–P-06, reopen Phase 002 discovery or Phase 001 purpose as appropriate. If behavior is actually missing, reopen Phase 003 rather than masking omissions with factoring vocabulary.
